# 访问边界与运维角色

所有公共API从Bearer凭证解析企业、主体、角色和应用动作范围，不信任请求中的tenant_id或user_id。跨企业及无权限资源统一不可见。知识库授权与文档收窄权限共同生效；read不包含download。

## 运维角色

新增OPS（运维）成员角色，由企业管理员创建/修改和签发凭证。OPS仅可GET `/api/v1/me`与`/api/v1/operations/status`；其他公共入口一律404。领域层同样拒绝OPS知识访问，因此误配知识库权限或责任人身份也不能赋予内容读取能力。

运行状态只返回当前企业的任务类型/状态计数、清理状态计数、生成状态计数和统计时间；不返回文档名、正文、问题、回答、资源ID、租约、密钥、模型地址或审计详情。OWNER/ADMIN也可查看；USER、DEVELOPER、KNOWLEDGE_MANAGER和应用身份不能调用该运维入口。前端OPS只显示运行状态导航，其他角色仍由各业务API授权。

Python同步/异步SDK提供operations_status，Java SDK提供operationsStatus。它们调用相同公共API，没有旁路访问。

## 应用与外发

应用访问任何知识资源必须同时满足有效应用凭证、动作范围、当前已发布应用绑定、知识库授权和文档授权。即使某知识库已向应用授权，未绑定时仍不能通过切片、父片段、原文或其他直接入口读取。移除绑定立即生效；配置草稿不授予权限。

每组Embedding查询外发前重新认证并复核检索版本范围；重排前逐片复核权威内容。生成前、继续交付文字/用量和保存答案前重新检查身份及证据。模型返回的ID不能替代Java授权。撤权不等待令牌过期；进行中的输出停止，历史每次读取重新检查依赖，失去任一资料访问权则隐藏整条依赖答案。

新增接口必须沿用这些边界并追加回归，尤其后续会话、引用定位和反馈任务，不能仅依赖前端导航隐藏。
