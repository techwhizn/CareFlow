# ADR 009：数据库轮转准入与有期限的任务通知

状态：采纳。

全局 FIFO outbox 与消费者对额度错误的立即重投会让单个企业拖延其他企业。改为 Java 持久化企业轮转游标，每企业最多一个待领取通知预留；调度和领取两次执行套餐检查。RabbitMQ 继续作为至少一次通知通道，执行权仍由数据库租约决定。

预留 120 秒，过期后重投；数据库事务外等待 broker 确认。全局最多 32 个有效通知预留，每轮发送最多 20 条。通知 token 防止迟到确认覆盖下一轮。内部已计数重试优先，避免任务额度耗尽阻断已付额度的重试。

数据库游标锁使多个调度器共享公平顺序，代价是准入短事务串行。未引入 Redis 双写或新的队列系统。公平性不等于任务抢占或 SLA；长任务受既有解析时间与资源上限约束。V1-45已记录本地2核CPU模型的容量限制，高并发部署需另行规划模型容量。
