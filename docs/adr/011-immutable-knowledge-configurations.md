# ADR 011：不可变知识库配置与按索引模型路由

状态：已采纳。日期：2026-09-10。

## 问题

只有全局Worker环境时，模型或切片参数调整会影响正在执行的任务；历史向量与新查询向量可能来自不同模型，无法安全回滚。仅保存一个可修改模型档案ID也不能固定处理行为。

## 决策

Java保存不可变知识库配置，冻结经授权模型档案的修订、地址、模型身份与加密凭证。配置发布采用独立CAS修订及追加历史，上传和重处理在事务中同时将内容版本和任务绑定配置。Worker接收类型化运行快照，用请求局部上下文调用模型，不修改进程环境。

查询先由Java筛选有权访问的已发布版本，再按原索引配置及身份分组召回。融合不同组的排名，之后按已冻结的查询策略进行重排和生成。公共响应不包含运行凭证。每次解析快照仍校验部署端点许可。

旧记录保持未绑定状态；只允许模型身份完全匹配的就绪索引进行一次明确绑定，否则创建新版本重新处理。模型身份不包含密钥，包含模型地址、名称、修订、维度和度量。升级不得自动猜测旧索引身份。

## 后果

发布配置与发布内容相互独立，正在运行任务和旧发布不会被配置切换改写。固定凭证意味着供应商撤销旧密钥后相关快照会失败，需要新的处理版本。多知识库查询策略不一致时显式拒绝，应用级查询策略由应用层工作包继续扩展。新增表与配置列需随数据库、对象、索引和加密主密钥一致备份；不能仅回退二进制。
