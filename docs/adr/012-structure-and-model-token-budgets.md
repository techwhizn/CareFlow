# ADR 012：结构切片与模型原生Token预算

状态：已采纳。日期：2026-09-10。

## 问题

通用Tokenizer计数不等于模型原生输入长度。长正文切分后还可能丢失标题、表头；把上下文拼入切片而不计数会再次超限。直接截断会丢失资料且破坏来源对应关系。

## 决策

Python的独立切片模块保留原始块和Unicode位置，按结构逐级退到Token预算；检索上下文单独记在来源元数据中，并纳入最终完整输入计数。

配置快照增加切片策略、上下文开关、模型计数方式及模型上限。支持匹配模型的cl100k计数，或同一获授权Embedding端点的 `/tokenize` 扩展。原生计数必须返回固定模型名称、修订、完整输入数量及上限；校验失败显式终止。按批量计数的结果继续细分正文，保留顺序、覆盖和原位置。

新解析、索引前与人工编辑均执行对应输入检查。Java继续拥有配置、权限与修订，Python负责计数和切片。原生计数调用不增加任意地址输入，复用已有模型端点许可与凭证快照；资料处理仍受隔离进程限额与取消约束。

## 后果

模型服务须提供与其实际Tokenizer一致的计数扩展，通用Embedding接口不自动满足此契约。BGE可由本仓库可选服务直接提供。计数不可用或标题无法放入输入窗口时失败，不使用近似计数掩盖问题。重排模型的成对输入窗口独立处理，不能从Embedding计数推断。配置JSON添加字段，Java与Worker协议需同步升级。
