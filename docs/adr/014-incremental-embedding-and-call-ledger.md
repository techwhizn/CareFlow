# ADR 014：内容向量复用与任务调用台账

状态：采纳，2026-09-10。

切片复制为新草稿会产生新ID，按ID缓存无法复用未变内容。Worker在Milvus建立独立缓存集合，集合名包含租户UUID与完整Embedding身份摘要（地址、模型、不可变修订、维度），主键为完整UTF-8内容的SHA-256。命中时再次比较完整文本及向量维度、有限数值。不同租户和模型身份不共享缓存；标签、来源和启用状态不改变向量身份。启用的业务切片仍分别写入检索集合，dense与原生BM25使用同一条记录的ID、版本和文本。

每批最多32条未命中文本调用模型，成功批次写入缓存。批内相同内容只计算一次；并发任务可能各自计算同一未命中内容，分别记录实际调用，不通过长数据库锁串行外部请求。缓存不可用或不一致明确失败，禁止伪造向量。

Java的`IndexAccountingService`拥有模型调用台账。Worker先在有效任务租约下登记调用，再发出请求，在写向量前回报供应商用量。调用标识幂等；缺失、非法用量或请求失败明确保留未知。已登记调用可在任务取消、租约失效后回报结果，但不恢复任务、不授予继续执行权限。已知用量同步写入`usage_events`，任务重试不会删除旧调用记录。

完成索引时Java核对当前启用切片数、新算文本数与复用切片数，并与当前租约的调用台账核对输入量和Token。整个核对与READY切换同事务。任务公开响应只提供计数和已知Token小计、未知调用数，不暴露租约和模型密钥。

迁移V21新增台账及任务计数字段。历史任务无法追溯实际调用，不回填0；新旧Worker需协调升级，旧Worker缺少计数的完成请求会被拒绝。旧索引首次在本机制下处理会填充缓存，以后相同内容可复用。失败调用的供应商账单追溯和其他资源统一结算属于V1-38；永久缺少回报的STARTED记录按未知展示，不能宣称已精确结算。

缓存属于敏感内容副本，须纳入V1-23清理策略。缓存不参与授权或发布决策。版本代际、完整索引核对和孤立记录补偿由V1-22实现。
