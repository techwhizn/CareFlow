# ADR 015：索引代际与完整核对

状态：采纳，2026-09-10。

同一切片ID原地写入无法隔离迟到Worker或失败的重建。新索引使用租户和完整模型身份分隔的`cf2_`集合，保留业务`chunk_id`，物理主键为代际UUID与切片UUID生成的UUIDv5；`generation_id`由Java在每次任务领取时分配。重试使用新代际，因此旧租约的外部写入只能成为待清理副本，不能覆盖有效记录。

Worker为每条记录同时写dense、BM25输入文本、版本、代际与浮点向量校验和。写入后通过[Milvus query_iterator](https://milvus.io/api-reference/pymilvus/v2.6.x/MilvusClient/Vector/query_iterator.md)逐批扫描整个版本代际，核对全部启用切片，检测缺失、多余、重复ID、文本差异、维度/非有限数值和向量校验和差异。校验和按Milvus的float32表示计算。返回按业务ID排序的`id:SHA256(UTF8内容)\n`清单摘要，Java独立计算并核对；核对不是抽样搜索。

Java拥有`index_generations`和`document_versions.active_index_generation`。任务完成事务在原租约有效、模型身份匹配、内容修订和前序代际不变、实际用量计数匹配、清单摘要一致时切换指针，将原代际标为RETIRED。失败/取消/过期尝试标为FAILED或CANCELLED，不改变当前有效代际。构建状态清理也收敛被批量取消的任务。

已发布内容不可编辑，重建期间版本保持READY，查询仍路由到旧代际；初次构建与未发布草稿保持原排队/索引状态，阻止并发修改。新代际启用不等于文档发布，也不改变应用绑定或权限。回滚文档仍按当前Java授权执行。

旧`cf_`集合无代际和向量校验和，读路径保留明确的迁移分支，旧记录核对文本/ID/维度；首次成功重建才切换到新集合。旧索引需要先绑定完全兼容的冻结模型配置。新索引任务缺少配置会终止，禁止悄悄使用变化后的进程默认模型。

公共核对接口在调用Worker前取内容快照，返回后重新验证凭证、租户、资源状态、内容修订与当前代际，再记录核对结果。报告仅返回计数及至多50个差异ID，不包含文档正文或密钥。模型、存储或协议失败不产生“核对通过”记录。

V22为新增迁移；Java、Worker API、consumer需同步升级。数据库失败时新代际不启用，重试会创建另一代际，未引用副本交给V1-23按保留期清理。当前不在任务线程里提前删除旧索引，以便失败补偿和诊断。
