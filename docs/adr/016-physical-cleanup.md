# ADR 016：持久化物理清理与缓存归属

状态：已采纳。日期：2026-09-10。

## 问题

逻辑删除只停止授权，不能清除原文件、向量缓存与正文历史。外部存储没有与MySQL共用事务，进程中断和迟到任务可能导致部分完成；直接删除共享缓存会破坏有效版本的复用。

## 决策

Java拥有清理范围、租约、期限、缓存归属和审计。删除资源后等待120秒；每一步领取5分钟租约，重新验证企业和资源已删除或代际失效。Worker只执行类型化、内部认证的Milvus操作，不自行判断业务授权。索引消费者每批写入前验证任务租约；新索引开始前，Java登记当前输入哈希及其最后使用代际。

清理请求形成知识库→文档→版本依赖，父请求等待全部子请求。版本清理依次删除全部匹配索引、Strong读确认、等待压实，再删除无有效引用的缓存并等待压实，最后清理S3全部版本及正文副本。中断保留阶段，幂等重试。旧代际24小时后可清理；当前代际始终受保护。失败退避上限1小时，7天期限逾期仍保持失败可见。

保留最小ID墓碑、用量台账与清理审计；修订、冲突、派生答案和审计正文详情清除。缓存改用`cfec2_`，旧`cfec_`无归属的派生缓存按企业整体淘汰；升级必须停止旧consumer。有效版本共享原文件或缓存时不删除共享数据。

受管MySQL快照默认保留30天，快照有明确格式与目录归属标记。只在显式指定根目录内淘汰过期受管目录；不跟随符号链接，不自动认领历史未知文件。每次成功备份执行淘汰，部署运维另行每日运行保留期命令。跨存储恢复和删除撤权重放由V1-46验收。

## 代价与边界

清理以存储删除核对和压实完成作为应用级完成条件；Milvus段文件由其GC按配置窗口回收，MySQL磁盘页、备份与存储介质不能据此宣称已安全擦除。外部S3锁、依赖中断和容量不足可能导致逾期，必须可追踪而不能伪造完成。运维参数、SDK入口及升级顺序见 [运行手册](../operations.md)。
