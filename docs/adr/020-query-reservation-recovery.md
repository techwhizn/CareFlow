# ADR-020：查询预占恢复依据持久化结果

日期：2026-09-11。

## 决策

Java的QueryReservationService统一拥有查询准入、额度预占、结算和异常恢复，检索服务委托调用。每次预占记录5分钟期限；定时器每15秒扫描最多100条过期记录，在企业行锁内重查状态并执行一次性结算或释放。

查询/答案保存事务同时标记result_committed。搜索仅在其查询记录成功保存时标记；问答检索得到证据尚不标记，直到答案及引用保存完成才标记。恢复时有完成标记则结算一次，否则释放；即使之后正文被物理清理，原完成事实仍然可用于计量。标记不保存任何正文。

过期执行无法保存新的查询记录或答案，不能通过迟到的成功回调重新扣费。每次模型调用开始前再次检查预占；已在供应商执行的调用可能直到其HTTP超时才结束，不能宣称外部消耗可瞬间撤销。模型账本独立保存已知消耗，迟到的生成用量回报可补充Token但不改变客户结算终态。

恢复清理当前请求持有的会话锁，不清理后续请求的锁。相同幂等键仍返回409，不自动重放或再次收费；新调用需使用新键。

## 升级与限制

V32新增expires_at和result_committed；旧预占从迁移起获得5分钟窗口，能关联已保存结果的记录补充完成标记。旧版本完全缺失结果关联的请求不伪造成功状态，过期后释放并保留供应商用量。滚动升级期间旧Java写入的无期限记录按创建时间+5分钟处理，旧执行节点需先排空再下线，避免旧逻辑绕过新增提交检查。

该规则面向当前单次查询额度，金额与价格快照由V1-39继续实现，不把供应商消耗自动换算为客户账单金额。
