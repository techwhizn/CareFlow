# ADR 024：停止服务冷备份与完整事务日志恢复

状态：实现及演练中，2026-09-11。

首版默认单机部署使用停止服务的跨卷快照，保存MySQL、文件和索引卷，并单独加密配置。在线快照需要存储层的一致性保障，不在当前工具能力内。工具要求独占维护窗口，拒绝运行中、共享或未知布局的卷。

恢复旧数据库会恢复旧授权。为了避免运维脚本重复实现Java的权限规则并遗漏表间关系，后续恢复使用MySQL完整事务日志前滚，不自行筛选“看起来与权限相关”的SQL。通过备份关闭时的日志文件摘要、源服务器身份及连续日志文件校验恢复链；缺日志、改写边界、不同来源或未知工具版本都拒绝继续。日志在单个数据库会话中执行，失败后目标保持关闭并从新空卷重新恢复。

增量导出要求源服务再次全部停止，导出当前末尾为止的日志。该记录证明所捕获源的截止状态，不证明异地灾难中不存在未归档的更新。管理员必须确认该截止点覆盖所有已接受写入；无法确认则不开放。长期部署还需将日志连续归档到独立存储，不能依赖唯一损坏节点上的日志。

数据库前滚不等于文件存储前滚。新增原文件需要对应文件备份，索引必须按数据库最新状态核对并重建；已删除资料即使仍在旧索引中，也必须由Java最新授权与状态阻止访问。工具仅恢复存储，不负责启动业务入口。恢复配置中的凭证始终视为敏感数据。

依据：[MySQL 8.4二进制日志恢复](https://dev.mysql.com/doc/refman/8.4/en/point-in-time-recovery-binlog.html)、[mysqlbinlog单会话重放与校验选项](https://dev.mysql.com/doc/refman/8.4/en/mysqlbinlog.html)。
