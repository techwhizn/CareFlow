# 表格语义与切片质量

表格行保留表名、列名中的原始单位注释及行列位置。CSV使用文件名，Excel使用工作表名，Word优先使用紧邻的Caption样式标题，Markdown使用所在标题路径。列标签原样保留，不推测缺失单位，不计算公式。

Markdown显式管道表格按行处理，围栏代码中的示例不识别为表格。每行携带表头上下文；复杂内嵌代码、转义分隔符、合并单元格、多行表头和PDF布局表格均需人工核对。超长行按既定Token预算分割，保留行标识和原始片段区间，并提示行被拆分。

`GET /api/v1/document-versions/{version}/quality?page=0` 返回内容修订、切片数、启用数、启用逻辑Token总量、长度分布、警告计数和每页100个问题。每个问题包含切片ID、原序号、切片页码和来源位置；权限与版本内容读取一致。Java SDK使用 `documentQuality`，Python同步/异步使用 `document_quality`。

检查规则：空内容/空表格行、少于20个逻辑Token、超过版本配置上限、空白归一后完全相同的内容、OCR人工核对、替换字符/异常控制字符、表头缺失/重复、行列数不匹配、表格行拆分和来源位置异常。重复不是语义近似检测；OCR警告不是识别准确率评分。空文件或无可读内容的文件在解析阶段显式失败。

检查采用只读事务和按序号分批读取，保持同一版本快照；不外发内容、不生成模型调用、不自动清理切片。人工修订后重新计算长度和重复，来源层的OCR或表格警告继续保留供对照。禁用片段仍显示在质量清单，但不计入启用内容Token总量。

Web工作台显示警告并定位相应原文片段，可继续修订内容。质量检查不是发布许可或事实审核：只有索引READY且内容修订未变更才可发布。计费规则和增量索引用量另见相应计量工作包，质量页逻辑Token不冒充模型账单。
