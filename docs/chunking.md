# 结构切片与模型输入窗口

知识库配置的 `chunking` 同时保存结构策略与输入预算。新配置发布只影响新上传和显式重处理；已发布内容、原切片及其来源不被原地改写。

| 参数 | 含义 |
| --- | --- |
| target / maximum / overlap | `cl100k_base` 目标、硬上限与正文重叠；`0 ≤ overlap < target ≤ maximum ≤ 600` |
| strategy | `recursive` 优先段落、换行、句子、分句、空白；`token` 按预算细分 |
| include_context | 每片加入完整标题路径、表名和可用列名；加入部分计入预算并单独标记 |
| model_tokenizer | `cl100k_base` 或 `provider`；前者仅适用于使用相同Tokenizer的模型 |
| model_maximum | 模型输入上限，1～131072；原生计数时再与服务真实上限取较小值 |

目标长度是切分偏好，硬上限始终校验。标题已占满目标但仍未达到硬上限时，用硬上限留出正文空间；标题或表头本身超过硬上限/模型窗口时失败，不能截掉标题或伪造资料。字符边界不切断Unicode；特殊Token字符串按普通资料文本处理。

`content` 是供检索的上下文和清理后正文；`source_text` 仍为原始区间。`location.context_prefix` 明确记录补充上下文，`block_start/block_end` 仍定位原始块，`block_ordinal` 保留原块顺序，模型再次细分后这些位置继续有效。表头是来源结构信息，不冒充当前正文中的重复原文。模型再次细分会把当前片段正文分为相邻区间，先前配置的重叠仍保留在原相邻片段之间。

## 原生计数服务

BGE等不同Tokenizer的模型应选择 `provider`。计数请求发往已授权Embedding地址的 `/tokenize`，复用该模型快照的认证和修订；不接受额外任意URL。使用外部Embedding时，资料也会发往同一获授权服务进行计数。

请求为 `{model, input: [text...]}`，每批最多32条。响应必须为：

```json
{
  "model": "BAAI/bge-small-zh-v1.5",
  "revision": "7999e1d3359715c523056ef9478215996d62a620",
  "counts": [12, 34],
  "max_input_tokens": 512
}
```

`counts` 包含模型自动增加的特殊Token，每条对应完整输入且不填充、不截断。模型与不可变修订必须与配置快照完全一致。长度错误、非法数值、修订不符、服务不可用或不支持此扩展都明确失败，不改用估算值。通用OpenAI兼容 `/embeddings` 不保证具有 `/tokenize`；接入方需提供同模型计数适配，或确认使用cl100k计数并配置正确上限。

切片器先按结构与逻辑预算生成候选，再批量原生计数，超限正文继续细分，保持原位置和顺序。新增计数在文档隔离进程中执行，仍受解析时间、内存和取消限制。计数只获取长度，不产生Embedding；输入与密钥不写日志。

索引前再次检查全部完整输入；人工编辑同样调用快照计数器，超限返回 `MODEL_INPUT_TOO_LONG`，不会保存或开始向量写入。计数失败返回明确错误。使用原生计数的任务报 `MODEL_TOKENIZER_UNAVAILABLE` 时，先确认模型服务就绪、接口与快照修订，再从任务中心重试。

本项保障切片及Embedding输入。重排的“问题＋候选”属于另一模型和Tokenizer，不能仅凭Embedding窗口推断其合法；本地模型服务也会拒绝超限重排输入。问答证据编排与重排输入处理继续由检索工作包完善。

## 升级

配置JSON增加可选字段，无需修改已应用的数据库迁移。旧配置缺失字段时使用 `recursive / true / cl100k_base / 600` 默认值，仍保持原目标、上限和重叠。切换为原生计数需要创建、发布新配置并重新处理，旧索引不变。恢复旧二进制前需要恢复匹配的配置备份，不能让旧协议读取带新字段的任务。
