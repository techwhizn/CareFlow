# 父子切片、FAQ 与人工补充

知识库配置增加 `chunking.layout`：`standard`、`parent_child`、`faq`；`parent_maximum` 默认1600 Token、硬上限1600。`strategy` 仍表示子片段的递归或Token切分方式。选择策略并发布配置后，通过新上传或“按当前配置重新处理”生成可预览的草稿；查看关系和来源后再索引、发布内容版本。

## 父子切片

父片段保存完整结构上下文，子片段用于Embedding及检索。每个子片段只关联同一租户、同一内容版本的父片段；数据库复合外键和Java任务回调均校验这一边界。回调只提交文档内编号，由Java生成真实ID；模型不能指定跨文档父片段ID。

复制草稿时复制父片段和FAQ组并分配新ID，再映射子片段关系。不能让新草稿复用旧发布的可修改上下文。父片段不作为独立Embedding记录；检索后的父片段扩展由V1-26继续完善。

## FAQ 文件

使用显式问题、可选相似问法和答案标记；示例见 [faq.md](../examples/faq.md)。推荐Markdown文件：

```text
问题：如何重置？
相似问法：怎么复位|重启步骤
答案：先核对设备状态，再按手册操作。
```

也接受 `Q/Question`、`A/Answer`、`Similar/Aliases`。相似问法用竖线分隔，最多20条、每条400字符；问题最多1000字符，答案最多8000字符，完整组仍须满足配置的父上下文Token预算。问题与答案之间只能有明确标记的相似问法，不能丢弃未标记的限定说明。缺少答案、未标记段落或整组超限时明确失败，不自动猜测关系。

问题、相似问法和答案分别保存。答案子片段包含问题及相似问法上下文，原始位置仍定位源文件的真实答案区间；上下文前缀不冒充原文。多个问题可以有相同答案，关系仍分别保存。

## 人工新增与修订

文档工作台的“人工补充FAQ”创建整组问题、相似问法与答案。组内子片段的编辑入口是“修订整组FAQ”，这样问题和所有答案片段保持关联。保存重新切片并使当前索引失效，需要重新索引和发布。

人工补充或修订的上下文及子片段标为 `MANUAL`，原文件区间为空，来源类型为 `manual`，不能构造页码或偏移；此前解析版本的原始来源保留在修订记录。未分组切片的普通编辑标为 `MANUAL_EDIT`，保留原文用于对照。

如需单独修订某个子片段，先“解除该组关联”。此操作保留组内各个切片、解除全部子片段对原上下文的引用，并记录原因；避免编辑后继续补充已不一致的旧上下文。已发布版本不能修改、解除分组或新增FAQ，须先复制草稿。

FAQ计数和细分在数据库事务外执行；保存前重新认证原请求凭证、复核权限、状态和用户观察的版本修订。期间凭证被撤销、权限变化、开始索引或版本已修改时拒绝提交，不覆盖并发变更。

## API 与 SDK

以下路径省略 `/api/v1/document-versions/{version}`：

| 方法 | 路径 | 输入 |
| --- | --- | --- |
| GET | `/contexts?page=0` | 同版本当前仍有关联的父片段或FAQ，每页100组 |
| GET | `/contexts/{id}` | 单组内容及来源，仍校验版本读取权限 |
| POST | `/faqs` | `revision, question, alternatives, answer, reason` |
| PUT | `/faqs/{id}` | 同上，整组修订 |
| POST | `/contexts/{id}/detach` | `revision, reason` |

`revision` 必须是预览时读取的内容版本修订，不自动替换成最新值。Python同步/异步提供 `document_contexts`、`document_context`、`save_faq`、`detach_context` 和 `FaqInput`；Java提供同名驼峰方法及 `FaqInput`。模型密钥不属于这些公共请求。

## 升级与恢复

V16新增上下文表、子片段引用及来源类型，V17保存组修订历史，V18分列保存FAQ答案。旧切片的引用为空，来源默认为解析，原始文本不变。停止消费者，先升级Java数据库和Worker协议，再恢复消费者，避免把新协议结果提交给旧服务。备份需包含新增表；恢复需保持版本、切片、上下文、模型配置及索引一致。不要只回退二进制，也不要修改已应用的迁移。
