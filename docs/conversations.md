# 多轮会话与历史访问

Java 保存会话、历史及授权依赖；Python 只计算上下文 Token 并调用生成模型。业务意图配置仍属于应用层。

## API

- `POST /api/v1/conversations`：传入 `application_id`（可省略）和 `knowledge_base_ids`（最多 20 项），建立当前主体的会话。
- `GET /api/v1/conversations`：当前主体最近更新的 100 个会话。
- `GET /api/v1/conversations/{id}`：会话元数据及当前可见的历史回答。
- `POST /api/v1/answers`：新增可选 `conversation_id`。省略时自动创建会话；继续追问需传回该 ID，并保持相同应用、知识库集合。
- `GET /api/v1/answers?conversation_id={id}`：指定会话最近 100 条可见回答。
- `GET /api/v1/answers/{id}`：重新授权后返回完整答案与当时的引用快照。

`start` 事件返回 `conversation_id`、`conversation_revision`、`context_rounds`、`context_tokens`；`done` 返回完成后的修订号。检索调试接口不接受会话 ID。

会话绑定租户、主体 ID、主体类型、应用及规范化知识库集合。应用凭证自动绑定自身应用。切换范围返回 `409 CONVERSATION_SCOPE_MISMATCH`，需新建会话；并发追问返回 `409 CONVERSATION_BUSY`。Web 切换知识库自动清空会话，也可主动新建。Java/Python SDK 提供同名功能。

## 上下文与授权

只考虑最近 6 个已完成问答；逐条重新授权后，从最新向前选取不超过 3000 个 `cl100k_base` Token 的连续后缀，计算文本为“问题 + 换行 + 答案”。遇到超预算轮次即停止，不截断答案。当前问题、系统提示与本次证据不计入这 3000 Token；证据另有 6000 Token 上限，供应商计费 Token 单独保存。

当前问题含型号或错误码时保持当前问题；否则将最近选定历史问题补入检索文本以解析指代。该规则是确定性上下文补充，不是模型意图识别。历史问答作为生成上下文，不能替代本次证据或授权。

引用依赖覆盖本次证据、父子扩展所包含的切片、历史答案的全部依赖。每次模型调用前、流式输出时和保存前重新校验；删除、禁用或撤权使整条受影响答案及引用不可读取。历史打开操作请求服务器，不直接信任页面缓存中的旧正文。

## 事务与异常

每个会话只允许一个在途请求，租约 150 秒，输出与保存均检查当前请求身份。成功保存答案、递增修订号和释放会话在同一事务；失败或取消不增加轮次。旧请求不能释放或提交新请求的会话。租约到期可重试；进程崩溃后的查询配额恢复另见计量恢复任务。

停止和连接异常保留“未完成”状态。服务器保存与网络确认不能原子提交，客户端仍必须收到 `done` 才认为成功。恢复后可从会话历史核对已保存答案。
