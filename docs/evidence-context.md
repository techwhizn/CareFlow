# 检索证据整理

Rerank仍只对已授权匹配切片评分，完成后Java读取同版本父片段或相邻片段来补全文本。模型返回的正文不作为权威资料；扩展来源从MySQL读取并复核权限。

父子/FAQ组的所有子片段启用且组规模不超过50片时使用完整父内容。任何子片段被禁用，整组父扩展被关闭，返回命中片段本身，避免重新引入禁用内容。未分组的标准切片补充前后各一片，限制为同版本、启用、未分组内容；相邻文本20～2000字符的精确首尾重叠只保留一次。扩展内容仍受10000字符协议上限约束，超过则保留原匹配切片。

同一匹配片段只处理一次，同一父组或已覆盖的匹配片段不重复占位。跨文档完全相同的空白归一文本也只保留一条。部分相邻扩展与已有证据重叠时，尚未覆盖的新命中退回自身内容；最多6条证据、同一文档最多3条。该规则只去除确定重复，不把语义相似但可能互相冲突的资料当作重复删除。

证据文本通过Worker本地cl100k_base批量计算实际逻辑Token；所有证据内容Token总和上限6000，代替旧的6000字符判断。超限证据以CONTEXT_TOKEN_LIMIT排除，重复以DUPLICATE_CONTEXT排除；不静默截断。对生成入口再次执行同一证据Token总量检查。问题、系统提示和协议包装不计入这6000个“证据Token”，模型对完整请求的实际窗口仍须满足。

响应包含evidence_tokens、evidence_token_limit与evidence_tokenizer；每条保留命中ID、matched_content、matched_token_count、context_kind、covered_chunk_ids、实际token_count；父片段另有context_location，相邻片段有context_locations。原location对应命中片段，扩展来源按新增字段追溯。Java/Python SDK保留这些响应字段。

这些逻辑Token用于产品预算，不能当模型账单。已验证本地BGE适配器对完整Embedding输入和Rerank问题-片段对采用原生Tokenizer、禁止截断并在512窗口超限时明确失败；外部生成服务拒绝输入或上下文超限也会显式失败，不伪造结果。模型用量与上下文能力需按所选供应商单独验证。
