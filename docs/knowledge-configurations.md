# 知识库配置版本

知识库详情的“管理配置版本”维护解析、切片、检索和三类模型配置。先在模型配置页建立已获部署许可的模型档案，再创建知识库配置。模型地址、名称、不可变 Embedding 修订、维度和凭证由服务端冻结；公共接口只返回档案引用与修订号。

## 保存、发布与回滚

保存产生不可变草稿，不改变运行配置。修改已有配置时复制为新草稿。请求必须带用户查看过的三个模型档案修订；档案已修改返回 `409 MODEL_PROFILE_CHANGED`，避免确认后悄悄选用另一模型。

发布前查看影响说明，并提交当前 `configuration_revision` 和原因。修订冲突返回409，需要重新核对。回滚是再次发布某个历史配置，产生新的发布历史与修订，不恢复历史权限或覆盖其他元数据。

发布配置后：

- 新上传和“按当前配置重新处理”绑定新的解析、切片和模型快照。
- 已接收任务、现有内容版本和它们的索引仍保留各自配置。
- 新查询使用当前发布配置的检索默认值、重排和生成模型；一次查询开始后冻结配置，途中发布不改变该次查询。
- 每个已授权内容版本使用其原 Embedding 配置召回。不同模型组用排名融合，不直接比较不同模型的原始分数。

切片逻辑预算采用 `cl100k_base`，`0 ≤ overlap < target ≤ maximum ≤ 600`；可另外选择模型原生计数和输入上限，超限继续细分。BGE应使用原生计数，不能把不同Tokenizer的数值直接比较，详见[切片与模型窗口](chunking.md)。PDF页数还受租户套餐限制，取两者较小值。

请求未传 `mode` 或传null时使用已发布检索模式；显式值覆盖模式。返回数不会超过配置上限；请求阈值不能降低配置阈值；混合检索降级还须得到配置及应用策略许可。多个知识库使用不同重排、生成或检索策略且未指定统一应用策略时，返回 `409 QUERY_CONFIGURATION_CONFLICT`；应用可发布统一查询模型和检索策略，详见[应用配置](application-policies.md)。查询Embedding仍按各索引版本的模型身份分组。

## 原有资料升级

迁移V15不为旧数据猜测配置。未绑定配置的旧索引使用部署模型，并强制核对已经保存的模型身份；修改环境不能让旧向量被新模型直接查询。

可在就绪历史版本上执行“绑定当前兼容配置”。需要知识库管理、文档编辑和版本发布权限，并提交所查看的内容修订。只有当前配置的 Embedding 地址、模型、不可变修订、维度、距离度量形成的身份与原索引完全一致时才能绑定；身份缺失或不一致拒绝。绑定只增加配置引用及修订，不改变切片或索引。绑定只能执行一次。

不兼容时使用“按当前配置重新处理”，从保留的原文件创建新内容版本；原发布继续服务，人工切片修订不会自动复制。完成解析、核对、索引后另行发布内容版本。归档知识库或归档文档不能创建重处理任务或兼容绑定。

## 密钥与运维

快照密钥使用现有AES-GCM密钥库，附加认证数据绑定租户和模型档案。只在受服务身份和租约保护的内部任务协议或Java到Worker调用中解密传输，不进入公共响应或日志。内部服务需部署于受保护网络并使用相应传输保护。

更新模型档案不会修改旧快照凭证。供应商吊销旧凭证后，依赖它的历史任务或查询会失败；需新建配置并重新处理，或在供应商支持时保留过渡凭证。部署管理员撤销端点许可后，旧快照也不能继续调用该地址。后台处理不能以伪造向量或生成文本掩盖失败。

升级前按备份流程保存MySQL、对象存储和索引，并保存模型加密主密钥。V15新增配置和发布历史表、知识库配置指针、任务与内容版本配置引用。未绑定旧记录保持NULL。升级后的配置可能依赖旧二进制不了解的模型路由，不能仅回退二进制继续处理；恢复需要一致的数据与模型配置备份。不要修改已经应用的V15迁移。

## REST 与客户端

公共入口：

| 方法 | 路径（省略 `/api/v1`） | 用途 |
| --- | --- | --- |
| GET/POST | `/knowledge-bases/{kb}/configurations` | 查看版本、创建草稿 |
| GET | `/knowledge-bases/{kb}/configuration-models` | 可选模型档案及修订 |
| GET | `/knowledge-bases/{kb}/configurations/{id}/impact` | 发布影响与当前修订 |
| POST | `/knowledge-bases/{kb}/configuration-publications` | 发布或回滚配置 |
| POST | `/document-versions/{id}/reprocess` | 原文件创建新处理版本 |
| POST | `/document-versions/{id}/configuration-binding` | 兼容旧索引绑定，正文 `{revision}` |

配置列表最多返回最新100个版本。历史ID仍可用于影响检查和回滚。Python同步、异步客户端及Java客户端均提供对应方法。模型密钥不属于 `KnowledgeConfiguration` 请求类型。SDK缺省Query模式为null，让服务端使用已发布配置。
