# CareFlow 人工验收流程：从上传到查询

本文面向测试人员、业务管理员和知识管理员。全程通过浏览器操作，不需要编程。目标是用一份可控的测试资料，确认“上传、解析、检查、索引、发布、查询和引用”整条链路可用。

## 1. 测试范围

本流程验证：登录和知识库权限、文件预估、文档版本和任务创建、Worker 解析与切片、索引、发布、检索、带引用问答以及失败排查。适用于 PDF、扫描 PDF、Markdown、TXT、CSV、DOCX、XLSX 和 PNG/JPEG。视频转写不在当前版本验证范围内。

## 2. 测试前准备

### 2.1 启动服务

在项目根目录执行：

```bash
docker compose up -d --build
docker compose ps
```

确认 `backend`、`web`、`worker-api`、`worker-consumer`、`mysql`、`rabbitmq`、`milvus` 和 `minio` 均为运行状态，然后打开 <http://localhost:5173>。

首次安装选择“初始化企业”，使用 `.env` 中的 `BOOTSTRAP_TOKEN`，并保存一次性显示的所有者凭证。已经初始化过的环境直接使用管理员凭证登录。本机测试也可以显式设置 `DEMO_AUTH_ENABLED=true`，使用登录页“测试模式快速进入”。

### 2.2 确认模型配置

完整链路至少需要 Embedding；混合检索通常还需要 Rerank；问答需要 Generation。DeepSeek 作为回答模型时：

```text
GENERATION_BASE_URL=https://api.deepseek.com
GENERATION_MODEL=deepseek-v4-flash
GENERATION_API_KEY=<服务端密钥>
```

密钥只放在服务端 `.env` 或密钥管理系统中，不要粘贴到测试资料、截图或 Issue。

### 2.3 准备测试资料

建议使用不含个人信息和真实机密的合成资料。新建 `careflow-manual-test.md`：

```markdown
# CF-100 设备维护

## 故障处理

设备显示 E404 时，先确认电源和网络指示灯，再重启设备。
如果重启后仍显示 E404，请记录设备编号并联系服务台。

## 服务时间

工作日服务时间为 09:00-18:00。
```

也可以将同样内容导出为 PDF；扫描 PDF 则使用包含上述文字的图片生成。文件应小于 50 MiB，PDF 页数不超过当前企业限制。

## 3. 浏览器操作流程

### 第一步：登录并打开知识库

进入“知识库”，打开一个可编辑的知识库；没有知识库时先新建并保存。预期结果是能看到上传、编辑切片、建立索引和发布操作。只读成员不应看到管理操作。

### 第二步：上传并完成预估

1. 在知识库详情页点击“上传文档”或“上传资料”。
2. 选择测试文件，等待状态从“正在预估”变为“待导入”。
3. 检查文件名、大小、费用状态和 OCR 页数。PDF 在解析前显示“待解析确定”属于正常情况。
4. 点击“开始导入”，等待状态变为“已接收”。

“已接收”只代表文件已保存并创建任务，不代表已经解析或发布。不要因页面刷新或网络变慢重复点击，先到“任务中心”检查是否已有同一任务。

### 第三步：等待解析完成

在“任务中心”找到文件对应的 `PARSE` 任务并记录任务 ID。等待状态从“排队中”“执行中”变为“已完成”，并确认没有失败阶段或错误码。失败时记录任务 ID、失败阶段、错误码和请求 ID。

### 第四步：检查解析内容和切片

打开文档详情和“切片工作台”，检查标题层级、段落顺序、列表、表格、型号、错误码和版本号。PDF 检查页码；Excel/CSV 检查工作表、行列或单元格位置；图片和扫描 PDF 检查 OCR 文字。搜索 `E404`、`CF-100` 和 `09:00-18:00`，确认没有丢失或拆坏。发现问题时编辑、拆分、合并或停用切片，并填写修改原因。不要发布未经核对的 OCR 结果。

### 第五步：建立索引

上传后系统默认会自动建立索引、等待任务完成并发布当前版本。确认切片检查完成后，在任务中心确认索引任务和发布状态；如果自动流程因配置或任务错误停止，可点击文档流程卡中的“建立索引”或“自动处理并发布”继续。在“索引检查”或“索引历史”中确认当前代次有效。Embedding、Milvus 或维度配置异常时必须显示失败，不能把局部成功当成完成。

### 第六步：发布文档版本

回到文档详情页，核对版本、切片、权限、标签和有效期。自动流程完成时发布记录会显示当前版本和操作者；若自动流程已暂停，再点击“发布此版本”并在影响提示中确认范围。预期结果是文档进入正常检索范围。

### 第七步：执行检索

在“检索”或“检索调试台”依次执行：

| 测试问题 | 建议模式 | 预期结果 |
| --- | --- | --- |
| `CF-100 显示 E404 怎么处理？` | 关键词/混合 | 命中故障处理切片 |
| `设备报错 E404 时应该先做什么？` | 语义/混合 | 命中同一处理内容 |
| `服务时间是什么？` | 混合 | 命中 09:00-18:00 切片 |
| `系统支持 E999 吗？` | 混合 | 无证据时返回资料不足或低置信结果 |

检查结果是否来自刚发布的文档和版本，且没有混入未发布、失效或无权限内容。

### 第八步：执行带引用问答

在“问答”页面提问 `CF-100 显示 E404 时应该如何处理？`，等待流式回答结束并显示“完成”。打开引用，检查文档、版本和页码/切片位置。再提问资料中没有的问题，例如 `CF-100 的保修年限是多少？`，预期是说明资料不足或拒答，不应编造。连接中断或模型超时时，页面应显示未完成或失败状态。

### 第九步：验证反馈闭环（可选）

在回答下方提交“有帮助”或“没帮助”反馈；对负面反馈填写原因。知识管理员进入“改进任务”确认反馈可追踪，修订资料后重新索引、验证并发布。

## 4. 失败排查

**预估失败**：确认文件不为空、小于 50 MiB、扩展名与真实格式一致。PDF 不能只是把 TXT 改名为 `.pdf`。重新选择文件即可重新预估，预估失败不会创建任务。

**服务暂不可用**：记录页面请求 ID和发生时间，在项目根目录执行：

```bash
docker compose logs --since=10m backend worker-api worker-consumer
```

按请求 ID、任务 ID或错误码搜索。不要粘贴凭证、模型密钥、完整业务正文或未脱敏日志。

**任务长时间排队**：检查 Worker、RabbitMQ 和企业处理并发限制。单机环境可能需要等待，不要重复提交。

**任务或索引失败**：查看失败阶段和错误码。常见原因是模型地址/密钥、Embedding 维度、Milvus、PDF 超页或加密、OCR 资源限制、文件损坏。修复后按页面“重试/重新处理”，再重新检查切片、索引和发布。

**查询无结果**：确认版本已发布、索引已完成、当前身份有读取权限、文档仍在有效期内。先用完整型号或错误码做关键词查询，再尝试语义和混合。

**引用打不开**：刷新后重新查询，确认引用对应当前可授权版本。撤权、归档或删除后，历史引用可能按设计不可读取。

## 5. 完成判定

文件预估和导入成功；解析、索引任务均完成；切片和来源经人工核对；版本已发布；关键词和语义问题命中正确证据；有证据的回答带正确引用；无证据问题不被编造；所有异常记录错误码、任务 ID/请求 ID和复测结果。

单次页面打开、单元测试通过或单独调用 DeepSeek，不能代替这条完整链路的人工验收。
