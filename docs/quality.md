# 开源质量基线

日期：2026-09-11。本文区分现有实现、已执行检查与待完成的发布条件。项目所有者已确定面向开源维护；已选择Apache-2.0许可证。

## 现有架构与差距

Java、Python、Web 的部署边界已存在，Java仍集中于 `com.careflow.platform` 包。V1-47已移除ManagementController和DocumentsController，按应用、初始化、身份管理、用量、文档读取、草稿、发布和任务读取划分服务。新控制器只映射协议，规则和事务由服务拥有；SQL归属对应服务或专用Repository，Db只执行SQL。

后续按业务需求继续收敛边界：

1. V1-30已将问答历史与会话规则移入服务/Repository；V1-32新增SearchService、FeedbackService、ImprovementService并移除AnswersController的SQL；检索内部仍有通用Map；不以拆文件数量宣称全部领域隔离。
2. V1-14上传已移出长事务，暂存补偿与模型/发布清理各自有边界；保持授权与事务回归。
3. V1-48已拆分知识库列表、详情与切片工作台，数据访问集中到功能模块；后续补更多浏览器场景与更精确的领域响应类型。
4. 逐步替换跨模块Map，下载边界已使用SourceFile记录；V1-48模型调用协议已补超时、空响应和断流契约测试；真实模型验收仍按对应工作包执行。

每次拆分保持公共API并记录回归证据。新增需求禁止重新在控制器堆叠业务逻辑。

## 自动化检查

| 层 | 当前合并检查 | 不能证明的内容 |
| --- | --- | --- |
| Java | Spotless、Maven verify 与现有行为测试 | 完整业务模块隔离、真实 MySQL 并发正确性 |
| Python | Ruff 静态检查和格式、pytest | 外部模型可用性、真实 Milvus 完整链路 |
| Web | TypeScript strict、单元测试、Chromium组件回归、生产构建与依赖审计 | 完整无障碍合规、其他浏览器及真实业务端到端正确性 |

工作流只授予读取代码权限；依赖更新由 Dependabot 提 PR，更新必须通过检查和评审。检查通过不能替代架构和安全评审。覆盖率不能代替对重要行为的验证。

## 文档维护

README 是可复现启动入口，CONTRIBUTING 是贡献入口，SECURITY 是漏洞处理入口。架构边界和决策分别写入 architecture.md 与 adr/；API、配置和运维变化必须更新对应文档。验收报告保留验证时间、环境和限制，旧报告不改写成新运行结果。

## 开源发布前必须完成

- 已添加Apache-2.0 LICENSE；继续检查第三方依赖及素材的许可与必要声明。
- 仓库链接、维护者与私密安全报告渠道已配置；远端分支保护仍需仓库管理员核验，已有[可审查方案](remote-ci.md)。
- 对拟发布内容与 Git 历史扫描凭证和敏感数据；确认示例与报告只含可公开数据。
- 在干净环境验证安装、迁移、构建和启动；真实检索/问答按发布范围验收。
- 补充关键浏览器流程测试；权限、并发发布、失败重试、模型流中断需有明确回归证据。
- 验证升级、备份恢复与已知限制，发布说明列出兼容性和未完成需求。

此基线不会把现有 0.1 增量自动变成生产可用版本；完成状态仍以需求表和实际验收证据为准。
