# 查询预占、结算与异常恢复

每次搜索/问答先预占一次查询额度，期限为5分钟。正常成功保存结果后结算；失败和取消释放。应用并发占用使用同一预占状态，释放时一并恢复。

进程崩溃、超时或数据库连接中断导致结算未执行时，Java每15秒处理一批最多100条过期预占：

- 已在同一事务内保存结果及完成标记：结算一次，不因重启丢失成功调用。
- 尚无完成标记：释放并在日志显示“超时回收”。问答只完成检索没有保存答案时属于这一类。
- 重复扫描、迟到结算不再次扣费。过期请求不能再保存结果或开始新的模型阶段。

恢复不将已知Embedding、Rerank或生成消耗归零；没有收到供应商用量时保留未知。已开始的外部模型请求可能继续到其请求超时，不能从释放客户额度推断供应商没有消耗。OCR及索引重试按各次调用分别记录，客户处理任务额度仍按原任务的一次性标记扣除。

查询幂等键重复返回409 `DUPLICATE_REQUEST`。返回`QUERY_EXPIRED`后需用新键发起新请求，重复旧键不会重新执行。日志的expires_at可用于排查预占释放时间。停止执行不会自动删除已保存的历史或供应商用量。

升级先新增V32表字段，再排空旧Java执行节点并运行新版；保留新列以便回退核对，不删除账本。历史缺失结果关联无法推断为成功，新规则不会伪造旧账单。设计依据见ADR-020。

专项证据：`reports/v1-38-crash-recovery-real.json`。在真实DeepSeek首个delta到达时SIGKILL本地Java，确认结果未提交且预占保留，然后只前移该合成请求的expires_at以缩短等待。重启后的真实定时器释放预占，已知检索Token保留，生成未知Token保持null，重复扫描不改写完成时间。旧键拒绝执行，新键成功调用。该测试验证实际进程中断和恢复路径，不宣称自然等待了5分钟。
