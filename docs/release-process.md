# 发布流程

当前仓库处于 0.1 开发增量阶段。发布流程用于准备可审查制品；未满足门禁时不得创建公开 Release、上传包或推送镜像。

## 发布前

1. 阅读 [任务清单](roadmap/v1.0-tasks.md)，确认所有适用功能、质量、安全和文档项有证据。
2. 运行贡献指南中的 Java、Python、Web、SDK、浏览器和敏感信息检查。
3. 执行依赖许可证、漏洞、容器和 SBOM 审计，记录工具版本、镜像摘要和未修复项。
4. 在干净目录构建 JAR/POM、Python wheel/sdist、Web 静态包和需要的镜像；源码归档只取已跟踪文件。
5. 对每个制品生成 SHA256，并在独立环境安装或加载验证；制品不得包含 `.env`、运行凭证、业务数据或模型权重。
6. 更新 `CHANGELOG.md`、兼容性、迁移、已知限制、许可证和第三方声明。

## 版本与标签

版本号遵循语义化版本的兼容承诺；未发布开发快照不得冒充稳定版。标签必须指向已经通过检查的提交，制品记录提交 SHA、目标架构和校验值。发布说明应明确模型供应商、外部服务、数据保留、低并发边界和不支持的平台。

## 发布后

维护者在获得明确账号和权限后，按仓库策略创建 Release 或上传包。发布动作与代码提交分开记录；不要把本地构建成功描述为远端发布成功。发现安全问题时立即按 [SECURITY.md](../SECURITY.md) 处理，并在必要时撤回或替换受影响制品。

## 当前状态

本地制品已可生成和校验，但人工质量评审、安全发现与远端 CI/分支保护仍是独立门禁。当前没有公开 Release、PyPI/Maven 上传或公开镜像发布。
