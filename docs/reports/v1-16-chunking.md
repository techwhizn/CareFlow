# V1-16 结构切片与输入预算验收

日期：2026-09-10。范围：结构递归、Token兜底、完整上下文计数与Embedding原生窗口。

## 结果

- 新切片模块支持结构递归及Token预算模式，目标、上限、重叠随配置保存。标题路径、表名、列名纳入内容和预算；原始切片区间单独保留。
- Unicode、特殊Token字符串、重叠覆盖、表头、跨块顺序、模型二次细分及非法模型计数有行为测试。无法容纳完整上下文明确失败。
- MySQL配置快照、真实BGE Tokenizer、隔离解析进程、BGE Embedding及Milvus完成长文链路。合成文档最终9片，最大逻辑155 Token、最大模型367 Token，均处于配置600和真实512窗口内；原始正文按顺序重组完全一致。详见[真实记录](v1-16-native-chunking-real.json)。
- 人工编辑使用真实Tokenizer：一段逻辑计数未超限、模型计数超过512的文本被Java拒绝保存。索引开始前再次检查，行为测试确认不合格内容不会进入索引或Embedding调用。
- 浏览器验证递归/Token选项、上下文开关、原生计数和输入上限；实际保存 `provider / 512` 草稿并读取API核对。Java与Python配置类型、OpenAPI及说明同步。

首次真实尝试遇到 `MODEL_TOKENIZER_UNAVAILABLE`，任务被明确标为失败，未提交切片或伪造成功。确认模型服务健康且计数接口返回固定修订后重新执行通过。此报告保留这一运行限制，不把服务启动阶段视为无故障。

## 检查和限制

后端92项、Python Worker70项、Python SDK20项、Java SDK7项、可选模型服务6项通过。Worker的1项外部集成默认跳过，实际模型与Milvus链路见上方单独记录。Spotless、Ruff和前端严格构建通过；单元测试包含明确替身，未作为真实模型证据。

本项不证明所有供应商已实现原生计数接口。接入方必须选择真实匹配的Tokenizer；原生接口缺失、返回模型修订不符或服务不可用会失败。它也不代表重排成对输入、全部证据编排、父子/FAQ切片或完整1.0已完成。配置和恢复限制见[切片文档](../chunking.md)。

提交前检查：Java保留授权及配置所有权；Python切片职责独立；模型返回数字与身份均校验；新增请求不引入任意URL；密钥与正文不进入日志；原始位置不被上下文拼接伪造。只执行本地提交。
