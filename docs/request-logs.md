# 调用日志与关联用量

企业管理身份可通过 `GET /usage/requests` 查看企业调用记录，通过 `/usage/requests/{request_id}` 查看明细。应用所有者、管理员、开发者及该应用自身READ凭证可使用 `/applications/{id}/requests` 及其请求明细路径。普通成员和其他应用不可读取。页面入口为套餐与用量、应用详情中的“调用日志与用量明细”，可直接按请求UUID查找。

列表返回 `items`（最多100条）和 `next_cursor`。把非空游标作为 `before` 获取更早记录。按开始时间及UUID稳定排序；游标必须属于当前企业/应用范围。明细只包含请求ID、应用ID、调用类型、状态、固定错误码、起止时间、配置ID、应用修订与模型用量，不包含问题、答案、证据、主体姓名、幂等键或真实密钥。

搜索返回的 `query_record_id` 与问答 `start.request_id`/`done.query_record_id` 即日志请求ID。每个请求可关联多个查询向量调用、一组重排调用和生成用量。额度结算与供应商消耗分别保留，取消或失败不清零已知Token。状态为RUNNING、SUCCEEDED、FAILED、CANCELLED；SUCCEEDED表示结果已保存并结算，不能证明客户端网络最终接收完整内容。

V31以前的记录用UNKNOWN显式说明缺失的操作和结果，不以当前应用配置倒填旧请求；未记录结束时间保持null。V31新增列均非破坏性。请求在应用限流、权限或幂等检查阶段拒绝时尚未创建执行账本，API保持原有404/409/429语义，不产生客户预占或模型消耗。

额度预占崩溃恢复见[查询恢复](query-recovery.md)。已完成的部分验收见V1-34三份真实报告；不能将此说明视为全部产品验收完成。
