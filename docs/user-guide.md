# CareFlow 用户操作手册

版本：0.1.0 开发增量  
适用对象：企业管理员、知识管理员、内容审核人员、普通使用者和运维查看人员

## 1. 先理解 CareFlow 在做什么

CareFlow 把企业散落在 PDF、Word、表格、Markdown、文本和图片里的资料，整理成可以搜索、可以问答、可以追溯来源的知识库。

你可以把它理解成一条“资料变成答案”的流水线：

1. **导入资料**：把文件放进指定知识库。
2. **解析资料**：系统读取文字、表格结构和图片中的文字，并标出来源位置。
3. **检查切片**：系统把长文拆成便于检索的小段，工作人员可以修改、拆分、合并或停用不合适的内容。
4. **建立索引**：系统为内容建立搜索索引。
5. **发布版本**：审核通过后，明确把这一版内容发布给使用者。
6. **搜索或问答**：使用者提问，系统返回答案和引用资料。
7. **反馈改进**：使用者对答案评价，管理员据此创建和跟踪改进任务。

解析完成、建立索引完成，并不等于内容已经对外生效；只有发布后，内容才进入正常检索和问答范围。

## 2. 页面导航和最短操作路径

登录后，左侧菜单按“工作空间、知识应用、企业管理”分组。普通使用者通常只需要“知识库问答”；知识管理员还会看到知识库和任务中心；企业管理员可维护成员、模型、应用和企业设置；运维查看人员只显示运行状态。

第一次导入资料时，按下面的最短路径操作即可：

1. 进入“知识库”，创建知识库并填写资料范围。
2. 打开知识库，上传 PDF、Word、表格、Markdown、文本或图片。
3. 在“任务中心”等待解析完成；失败时先打开任务详情查看阶段和原因。
4. 打开文档详情，在切片工作台对照来源原文，必要时编辑切片或文档信息。
5. 上传成功后系统会自动等待解析、建立索引并发布当前版本；仍建议在发布前抽查关键切片。若自动流程因缺少配置或任务失败而停止，可按页面提示处理后再次执行。
6. 进入“知识库问答”，直接提问并打开答案下方的引用来源核对依据。
7. 对答案选择“有帮助”或“没帮助”，把问题交给知识管理员改进。

页面上的“草稿”只对编辑人员可见，“已发布”才会参与普通检索。菜单中没有某个页面时，通常是当前角色没有该页面权限。

### 2.1 常见状态

| 页面显示 | 含义和下一步 |
| --- | --- |
| 草稿 | 正在编辑，尚未进入线上检索；检查后建立索引并发布 |
| 解析中 / 排队中 | 文件或任务等待处理；在任务中心查看进度 |
| 已解析 | 文字已提取；还需要检查切片并建立索引 |
| 已索引 | 搜索结构已生成；还需要发布才对使用者生效 |
| 已发布 | 当前版本可被有权限的搜索和问答使用 |
| 失败 | 处理没有完成；查看失败阶段和请求 ID，修订资料后重试 |
| 已删除 | 业务访问已停止，后台清理随后处理；不能在页面直接恢复 |

## 3. 登录前的准备

### 3.1 你需要什么

- 浏览器访问 CareFlow 地址；默认本机地址是 `http://localhost:5173`。
- 管理员为你提供一次性访问凭证或企业统一登录入口。
- 如果企业启用了 MFA，还需要身份验证器生成的 6 位验证码。

访问凭证和 MFA 密钥属于个人信息，不要发到群聊、截图、Issue 或工单正文中。凭证只在创建时显示一次；遗失时请联系企业管理员重新签发。

如果是本机测试环境，管理员可以在 `.env` 明确设置 `DEMO_AUTH_ENABLED=true`。登录页随后会显示“测试模式快速进入”，为已初始化企业的所有者签发 8 小时测试凭证。这个开关默认关闭，生产环境必须保持关闭；测试模式仍会记录审计，并继续执行资源权限检查。

### 3.2 认识角色

| 角色 | 适合做什么 |
| --- | --- |
| OWNER（所有者） | 管理企业、管理员、模型连接和全部企业级设置 |
| ADMIN（管理员） | 管理成员、应用、知识库授权、模型配置和运营信息 |
| KNOWLEDGE_MANAGER（知识管理员） | 管理指定知识库的资料、切片、索引、发布和权限 |
| MEMBER（成员） | 按授权查看知识、搜索和进行问答 |
| OPS（运维查看） | 查看任务、清理、告警和运行汇总，不查看知识正文或密钥 |
| 应用凭证 | 供其他系统按授权调用搜索或问答，不代表某个个人 |

你在页面上看不到某个资源，通常表示没有该资源权限；系统会用统一的“无法访问”提示保护企业资料是否存在的信息。

## 4. 第一次使用：初始化企业

只有部署管理员需要做初始化，普通使用者跳过本节。

### 4.1 找到初始化密钥

CareFlow **没有通用或默认的初始化密钥**。运行 `python3 scripts/init-local-env.py` 后，密钥会随机写入项目根目录的 `.env` 文件中的 `BOOTSTRAP_TOKEN`。不要把这个值粘贴到聊天、截图或代码仓库。

推荐在部署机上直接复制而不显示密钥：

```bash
python3 scripts/copy-bootstrap-token.py
```

首次生成环境时，也可以一步完成生成和复制：

```bash
python3 scripts/init-local-env.py --copy-bootstrap-token
```

如果系统没有可用剪贴板工具，再使用平台命令：

```bash
sed -n 's/^BOOTSTRAP_TOKEN=//p' .env | pbcopy
```

然后把剪贴板内容粘贴到登录页的“初始化密钥”输入框。Linux 桌面环境可使用系统对应的剪贴板工具，或在受控终端中读取 `.env`。

如果你刚修改过 `.env`，必须重新创建后端容器使新值生效：

```bash
docker compose up -d --force-recreate backend
```

### 4.2 创建企业

1. 打开 CareFlow 首页，选择“初始化企业”。
2. 输入部署环境提供的初始化密钥、企业名称和所有者姓名。
3. 提交后保存显示的一次性所有者凭证。建议立即放入企业密码管理器。
4. 使用刚显示的一次性所有者凭证登录。若部署配置了固定 `DEFAULT_ACCESS_TOKEN`，也可以暂时使用它进入，但页面会提示该凭证不安全；点击“前往修改”进入成员管理，签发新的个人凭证并撤销默认凭证，再为其他人员创建凭证和角色。

初始化只能成功一次。不要反复尝试，也不要把初始化密钥写进前端配置或提交到代码仓库。

## 5. 创建和整理知识库

### 5.1 创建知识库

1. 打开“知识库”页面，选择“创建知识库”。
2. 填写简洁、明确的名称，例如“售后产品手册”或“研发接口规范”。
3. 在说明中写清资料范围、适用部门和使用场景。
4. 创建后进入知识库详情页。

一个知识库建议围绕相近的资料范围建立。产品手册、财务制度和研发代码可以分别建库，之后再通过授权决定谁能使用。

### 5.2 设置责任人和标签

在知识库设置中可以修改名称、说明、语言、标签和责任人。责任人必须是企业内仍处于启用状态的知识管理角色。转交责任人会立即改变管理权限，转交前应确认新责任人能够继续处理任务和发布内容。

标签用于查找和管理，不会自动改变资料内容。修改设置时如果看到“版本冲突”，说明其他人已经保存过新版本；请先重新加载页面，确认最新内容后再保存。

## 6. 导入资料

### 6.1 支持的资料

当前可导入：

- PDF（包括扫描 PDF）；
- Word、Excel 等 Office 文档；
- Markdown 和纯文本；
- 常见表格文件；
- PNG/JPEG 等图片（通过 OCR 识别文字）。

视频转写、GPU 推理和高并发批量处理不属于当前版本的承诺范围。

### 6.2 上传步骤

1. 在知识库详情页选择“上传文档”。
2. 选择文件，确认文件名和目标知识库。
3. 等待页面提示任务已创建，然后到“任务中心”查看状态。
4. 不要因为页面短暂刷新或网络中断就重复上传；先查看是否已经存在同一任务。

任务状态通常包括排队中、执行中、已完成、失败、已取消和等待重试。失败时打开任务详情，查看“失败阶段”和错误提示。系统不会用假数据掩盖解析、模型或索引服务故障。

上传后文档详情会显示“正在处理此文档”和当前阶段，并每 3 秒自动更新状态；看到“解析中”或“排队中”是正常的，不需要手动刷新页面。解析完成后系统会自动建立索引并发布，处理完成后状态会自动变为“已发布”。

### 6.3 解析质量检查

解析完成后打开文档详情，重点检查：

- 标题层级是否正确；
- 表格的列名、单位和行关系是否保留；
- 图片或扫描件中的文字是否有识别错误；
- 代码、型号、错误码、版本号是否完整；
- 每个切片是否能定位到页码或原文位置；
- 是否混入不应公开的个人信息、密钥或内部备注。

发现问题时，先编辑切片或文档元数据，再继续建立索引。不要直接发布未经核对的 OCR 结果。

## 7. 编辑切片并发布

### 7.1 为什么要检查切片

检索不是直接读取整份文件，而是从切片中寻找证据。切片过大，答案可能抓不到关键段落；切片过小，条件、单位和上下文可能被拆散。因此发布前应让熟悉业务的人检查切片。

### 7.2 修改切片

在文档详情的切片工作台中，可以：

- 修改文字；
- 拆分一个切片；
- 合并相邻切片；
- 停用错误、重复或不应检索的切片；
- 填写修改原因；
- 查看修订历史和冲突。

保存时必须使用页面显示的最新修订号。出现版本冲突时，不要覆盖提交；重新加载后比较双方修改，再决定保留哪一版。

质量检查提示是只读诊断，不需要逐条点击“核对通过”。核对时在切片工作台左右对照原文；有误就编辑切片并填写原因，无误则继续检查下一条。全部检查完成后重新索引并发布，这一发布动作代表本轮核对结果进入线上版本。

### 7.3 建立索引

切片核对完成后选择“建立索引”。系统会进行向量化、关键词索引和必要的重排准备。索引任务完成后，先用检索调试台检查型号、错误码、同义问题和关键过滤条件。

### 7.4 发布、回滚和归档

- **发布**：让选定文档版本进入正常检索和问答。
- **回滚**：选择已经存在的旧版本重新发布；回滚不会恢复后来撤销的权限。
- **归档知识库**：停止新的检索和处理，但保留资料和发布记录，之后可由知识管理员恢复。
- **删除知识库**：立即对普通使用者不可见，并进入物理清理流程。删除前应查看影响预览，确认关联文档、答案和应用。

发布前确认文档标题、版本、有效期、标签和权限。发布后再修改草稿不会自动改变线上版本，必须重新建立索引并再次发布。

## 8. 文档元数据和有效期

文档元数据包括标题、来源、语言、标签、产品型号、有效开始时间和有效结束时间。

- 有效期为空表示不限制；
- 开始时间包含在范围内，结束时间不包含在范围内；
- 时间请填写带时区的格式，例如 `2026-09-10T09:00:00+08:00`；
- 失效文档不会进入默认检索和证据引用；
- 修改元数据不会自动重新发布内容。

来源地址只作为记录保存，系统不会自动抓取该地址。不要把带访问令牌的 URL 写入来源字段。

## 9. 搜索和问答

### 9.1 搜索

在“检索”页面输入完整问题、产品型号或错误码。可以选择：

- **关键词**：适合精确型号、错误码、编号；
- **语义**：适合换一种说法描述同一个问题；
- **混合**：同时使用关键词和语义，通常是默认选择。

可以按知识库、标签、型号和有效期筛选。调试信息只对有权限的人员开放，且不会显示未授权资料。

### 9.2 问答

侧边栏中的“知识库问答”是统一入口，会逐步显示回答，并附带引用。页面同时提供连续会话、历史回答、引用来源和反馈能力；不再需要在“知识库问答”和“引用回答”之间切换。阅读答案时请同时查看引用的文档、版本、页码或切片位置。引用缺失、与问题不相关或无法支持答案时，不要把回答当成事实，应改用搜索或联系知识管理员。

回答正在生成时可以取消。页面显示连接结束不代表回答已经完成；以“完成”状态为准。

系统没有证据时会拒答或提示资料不足，不应要求它猜测。模型输出不会自动获得企业权限，也不会直接执行转账、改配置、发通知等敏感动作。

## 10. 评价答案和推动改进

1. 在回答下方选择“有帮助”或“没帮助”。
2. 如果没帮助，选择最接近的原因，例如“没有回答问题”“引用不准确”“资料过期”或“应该拒答”。
3. 必要时补充简短说明，避免粘贴密码、身份证号、客户隐私或完整业务正文。
4. 知识管理员在“改进任务”中确认问题，修订文档、切片、权限或应用配置。
5. 修订后重新索引、验证并发布，再关闭改进任务。

管理员可以查看租户级反馈汇总和改进任务状态。汇总只包含数量和分类，不显示普通成员的问题和答案正文。

## 11. 成员、权限和应用

### 11.1 成员管理

管理员在成员页面创建成员、调整角色、禁用或移除成员。禁用和移除会立即使个人凭证失效；重新启用不会恢复旧凭证，需要重新签发。

移除知识库负责人前，必须先把知识库交给新的责任人。系统保留必要的审计记录，不建议通过共享个人凭证代替成员管理。

每位成员也可以在左下角个人菜单选择“更换我的访问凭证”。确认后旧凭证立即失效，新凭证只显示一次；请先复制保存，再关闭提示窗口。

### 11.2 权限编辑

知识库和文档权限是“全量替换”。保存前请确认页面列出的全部成员和应用都在授权清单中；提交后未列出的授权会被移除。文档权限不能超过其所属知识库权限。

权限变更遇到版本冲突时，先重新加载。不要重复点击提交，也不要用客户端自行填写的企业或用户身份绕过服务端校验。

### 11.3 应用凭证

应用凭证用于外部系统调用公共 API。创建时选择有效期和动作范围，密钥只显示一次。推荐流程是：先创建新密钥并完成切换，再撤销旧密钥。删除或到期后立即失效。

应用只能访问已绑定且被授权的知识库。应用凭证不等同于个人身份，也不能代替 MFA 管理操作。

应用中心中的应用可以直接删除。删除前会要求二次确认；删除会立即使该应用及其 API Key 失效，同时清理应用配置、发布记录和知识库绑定。删除操作会写入审计记录，已产生的用量和历史审计按企业保留策略处理。

### 11.4 企业设置

企业所有者或管理员打开“企业设置”即可修改企业名称。保存时系统会校验页面中的版本号；如果提示版本冲突，先刷新页面再重新提交。名称修改会立即显示在工作空间和登录后的导航区域，不会改变成员、知识库、应用或权限。每次修改都会写入审计日志。

## 12. MFA 和企业统一登录

### 12.1 启用 MFA

1. 在个人安全设置中选择“开始绑定 MFA”。
2. 将页面显示的密钥录入企业认可的身份验证器。
3. 输入身份验证器当前生成的 6 位验证码并启用。
4. 使用新验证码重新执行一次普通操作，确认已生效。

启用后，普通成员请求需要同时提供凭证和当前 MFA 验证码。MFA 密钥不会在页面或 API 中返回。遗失验证器时联系管理员按企业流程重置，不要把密钥发送给他人。

### 12.2 企业统一登录

如果企业配置了 OIDC，登录页会提供统一身份认证入口。只有管理员事先绑定的外部身份才能换取 CareFlow 成员凭证；系统不会根据 IdP 的任意声明自动创建成员或提升角色。

遇到 `SSO_UNAVAILABLE`，通常是企业身份服务暂时不可用或配置不完整，请联系管理员，不要反复提交外部令牌。

## 13. 管理员日常运维

管理员和运维查看人员可在“运行状态”和“任务中心”关注：

- 排队、执行、失败和超时回收的任务；
- 解析、索引和回答生成状态；
- 物理清理是否受阻；
- 查询失败和待回收预占；
- 集成 Webhook 投递失败和重试次数。

失败任务先看阶段和错误类型，再决定重试、修订资料或联系运维。不要直接删除数据库记录来“清除”失败状态。

### 13.1 备份和恢复

备份、恢复和密钥轮换由部署运维人员按[恢复手册](recovery.md)执行。恢复前必须核对备份清单、密钥、成员撤权和删除记录；无法确认时保持系统入口关闭。普通业务人员不应直接操作备份目录或加密密钥。

### 13.2 数据删除和保留

删除知识库会先立即撤销业务可见性，再由清理任务处理原文件、切片、缓存、索引和关联投递。查询正文、选项、审计和集成投递按企业保留策略处理。需要保留证据时，应在删除前联系管理员完成合规留存。

## 14. 常见问题

**问：上传成功后为什么搜不到？**  
答：检查解析任务、索引任务和发布状态；只有发布版本才会进入普通检索。再确认你的账号有知识库读取权限且文档仍在有效期内。

**问：回答看起来正确，但没有引用，能不能直接使用？**  
答：不能。CareFlow 的回答应以可查看的证据为依据；没有引用或引用不支持答案时，请改用搜索并反馈问题。

**问：页面显示“版本冲突”怎么办？**  
答：其他人先保存了修改。重新加载最新版本，比较内容后再提交，不要强行覆盖。

**问：任务一直排队怎么办？**  
答：查看运行状态和失败告警。单机低并发环境下任务可能依次处理；如果超过企业设定的等待时间仍无变化，记录任务 ID 联系管理员。

**问：能不能把视频直接上传？**  
答：当前版本没有承诺视频转写。请先将视频整理为文字、字幕或会议纪要后导入。

**问：模型服务不可用时会不会返回示例答案？**  
答：不会。系统会明确提示模型或检索服务不可用，避免把伪造结果当成企业知识。

## 15. 获得帮助时应提供什么

请提供页面名称、操作时间、任务 ID 或请求 ID、错误代码和脱敏后的操作步骤。不要提供访问凭证、API Key、MFA 密钥、客户个人数据或完整业务正文。技术管理员可进一步参考[API 文档](api.md)、[故障排查](troubleshooting.md)和[运维手册](operations.md)。
